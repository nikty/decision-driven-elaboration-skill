# Decision-Driven Elaboration

**Decision-Driven Elaboration** — скилл для пошаговой проработки функциональности продукта или системы через принятие решений.

Вместо того чтобы сразу генерировать спецификацию, скилл выявляет существенные неопределённости и помогает последовательно их разрешать. Он задаёт **по одному вопросу за раз**, предлагает 2–3 варианта поведения системы, объясняет последствия и даёт рекомендацию. Принятые решения фиксируются и учитываются в дальнейшем обсуждении.

По запросу скилл преобразует согласованные решения в **проверяемые требования в формате EARS**, не додумывая поведение, которое ещё не было определено.

## Пример использования

**Пользователь:**
> Используй @Decision-Driven Elaboration. Хочу проработать механизм автоматического сохранения конфигурации сетевого устройства.

**Ассистент:**
> Начнём с момента сохранения конфигурации.
>
> **A.** Сохранять каждое изменение немедленно. Минимальный риск потери данных, но больше операций записи.
>
> **B.** Сохранять изменения после периода неактивности. Меньше операций записи, но возможна потеря последних изменений.
>
> **Рекомендация:** B, если допустима небольшая задержка сохранения.
>
> Какой вариант выбираем?

**Пользователь:**
> B. Задержка 30 секунд.

**Ассистент:**
> **Согласовано:** конфигурация автоматически сохраняется через 30 секунд после последнего изменения.
>
> Следующий вопрос: что должно происходить, если устройство перезагружается до истечения этого интервала?
>
> **A.** Сохранить изменения перед перезагрузкой.
>
> **B.** Перезагрузить устройство без сохранения.
>
> **Рекомендация:** A, чтобы избежать потери изменений.

Обсуждение продолжается, пока существенные вопросы не будут разрешены. После этого пользователь может запросить итоговую спецификацию:

> Сформируй требования в формате EARS на основе принятых решений.
